# Risk Assessment — 重构风险与 S.U.P.E.R 健康总览

最后更新：2026-08-02（Phase 1 分析）

## S.U.P.E.R 健康总览

综合 2/3/4/2/3 → **平均 2.8/5**。核心问题：单文件混合架构阻碍状态扩展（记忆、调试、策略）。

## 主要风险

| 风险 | 等级 | 说明与缓解 |
|---|---|---|
| 重构期间线上停摆 | 中 | 重构期间战术脚本继续后台运行（旧代码），新架构测试通过后无缝切换；AGENT 槽位约束要求同一时刻只有一个提交方 |
| 行为回归 | 高 | 38 例测试覆盖决策分支；重构后测试全部保留并新增模块级测试；上线前用 diagnose 对比新旧决策输出 |
| 确定性破坏 | 高 | 记忆层引入跨 Tick 状态可能破坏"同输入同输出"；设计上记忆只做"附加线索"，决策主路径仍基于当前 Turn 权威状态；确定性测试保留 |
| 状态机复杂度 | 中 | Worker 状态机（巡逻→采集→回运→交付）需要事件驱动；简化：状态转移只由当前 Turn 触发，不做 tick 内并发 |
| 调试接口安全 | 中 | HTTP 调试端点仅绑 127.0.0.1，无鉴权需求（本地单用户）；指令接口校验动作白名单 |
| 记忆层数据陈旧 | 中 | 规则明确"视野外不可信"：记忆只标记 stale，决策永远优先当前 Turn 可见数据 |
| uv 迁移 | 低 | uv 已装；pyproject.toml + `uv sync`；SDK 版本钉死 0.2.6 |
