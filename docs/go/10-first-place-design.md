> 来源：Arena Hero 榜单第一名算法说明（2026-08-06 整理为工程设计文档格式）。
> 定位：**融合线（Rust 决策内核）策略层设计基准**——与
> `docs/go/09-rival-analysis.md`（第二名）对照，供 rust-rewrite/sim-rs

## 1. 算法定位

该算法是一套**基于实时状态重规划的确定性策略系统（Deterministic State-Based Planner）**。

核心思想：

> 不为单位设置固定行为，而是在每个 Tick 根据当前游戏状态重新计算最优行动。

系统每个 Tick 输入：

- 当前地图状态；
- 己方单位状态；
- 敌方单位状态；
- 资源状态；
- Core 状态；
- 历史记忆。

输出：

- 每个单位目标；
- 移动路径；
- 攻击目标；
- 防守策略；
- 探索方向。

## 2. 总体决策优先级

算法不是简单收益最大化，而采用状态优先级：

```
用户手动指令
        ↓
Core 生存与防御
        ↓
正在发生的战斗
        ↓
己方单位救援
        ↓
Worker 资源采集
        ↓
地图探索
        ↓
安全巡逻
```

### 核心原则

**生存优先**：Core 死亡一切经济归零——不为了短期资源牺牲 Core。

**稳定优先**：不因局部评分变化频繁改变目标（Worker 采矿途中出现更近矿点不
立即转向），避免 A→B→A、单位震荡、路线浪费。

## 3. 目标选择系统

### 3.1 多因素目标评分

每个候选目标计算综合评分（非"距离最近 = 最优"）：

```
Score = 距离收益 + 时间成本 + 战略价值 + 风险 + 当前任务状态
```

| 因素 | 说明 |
| --- | --- |
| 到达距离 | 单位当前位置、目标位置、路径长度 |
| 到达时间 | 预计 Tick = 路径长度 / 移动速度（避免到达时目标失效） |
| 返回成本 | 资源点 → Worker → Core 完整收益（不是只看采集） |
| 风险 | 附近敌人、危险区域、可能被攻击 |
| 任务稳定性 | 当前目标仍合理则继续；不可达/风险剧增/高优先级事件才切换 |

## 4. 寻路系统

### 4.1 A* 障碍感知寻路

曼哈顿距离 `h(n)=|x1-x2|+|y1-y2|` 只作为启发函数，不是最终路径——
直线最近不代表可达（障碍包围、敌方占位、封锁）。

### 4.2 路径稳定机制

每次规划检查：

- 是否已经到达（避免重复移动）；
- 是否出现 A→B→A 循环；
- 是否因局部评分变化反复改变方向（Tick1 左 / Tick2 右 / Tick3 左 → 禁止）；
- 是否进入封闭区域（无出口 → 重新规划）。

## 5. 单位预约系统（避免堵塞）

### 5.1 普通格子

一个 Tick 一个格子最多一个单位进入（避免 Worker 堵死）。

### 5.2 Core 特殊处理

Core 允许多个 Worker 进入附近区域，但必须调度：Core 当前容量、离开单位、
入口流量——不是所有 Worker 同时冲 Core。

### 5.3 全局交通调度

多单位冲突时比较：谁更需要该位置、谁已确定路线、谁距离更近；释放已完成
任务的单位。

## 6. Worker 资源系统（核心）

### 6.1 全局资源匹配

不是"Worker 找最近资源"，而是所有 Worker + 所有资源点 + 当前任务状态做
**全局匹配**：

- Worker 到资源距离（越近越好）；
- 返回 Core 距离（资源近但离 Core 远则收益低）；
- 当前任务（正在采集不轻易切换）；
- 资源竞争（一个资源只能分配一个 Worker）；
- Core 容量（Core 满则降低返回优先级）。

最终得到：`Worker A → Resource X / Worker B → Resource Y / Worker C → Scout`。

### 6.2 Worker 生命周期

- 空载：寻找资源 → 移动 → 采集 → 返回 Core → 提交资源 → 重新分配；
- 满载优先级：安全返回 Core > 继续探索 > 其他任务；
- 资源提交后重新判断：新资源 / 探索 / 防守。

## 7. 资源记忆系统

- **已知资源**：坐标、数量、时间；
- **失败路线**：多次无法到达 → 降低优先级；
- **暂时离开视野**不认为消失（视野有限）；地图确认不存在才删除。

## 8. 地图探索系统

三类区域：

| 区域 | 用途 |
| --- | --- |
| 当前可见 | 实时：单位/障碍/资源/敌人 |
| 历史区域 | 预测资源、地形、敌人 |
| 未探索区域 | 未知 |

## 9. 分区探索

地图切 Chunk，每个单位负责不同区域（避免全部同方向）；优先：最近未探索、
长时间未观察、资源概率高区域。

## 10. 不可探索区域剪枝

完全被障碍包围 / 无入口 / 无资源价值 → 标记 Forbidden，不再浪费单位。

## 11. 历史区域复查

历史地图非永久正确（新敌人、地图变化）——空闲时期低频重新检查。

## 12. 敌人威胁记忆

敌人离开视野仍保留：最后位置、时间、移动方向、威胁等级（消失不等于死亡）。

## 13. 静止敌人与移动敌人

- 静止：多 Tick 位置不变 → 可考虑攻击、作为固定威胁；
- 活跃：最近移动/攻击/接近 → 提高威胁等级。

## 14. 敌人移动预测

先判断关系（敌人追我 / 我追敌人 / 敌人逃跑 / 无关系），再结合最近运动方向、
当前目标、障碍、可行路线预测未来位置。

## 15. 战斗策略

- **Core 优先攻击**：发现敌方 Core 优先级最高；己方 Core 危险则防御优先；
- **攻击目标不是固定点**：预测区域（当前位置 + 预测移动方向 + 可能路线）；
- **攻击条件**：血量安全、有收益、不影响 Core；
- **撤退条件**：预计死亡、被包围、Core 受威胁。

## 16. 包抄与堵路

敌人逃跑不是所有单位追，而是前方拦截 + 侧面包围 + 后方追击；两种堵路：
直接堵路（占据敌人路线）、战术堵路（逼迫改变方向，获得移动信息与战术优势）。

## 17. Core 防御

重点防御区而非所有单位围 Core：Ranger 远程外围、Vanguard 近距离屏障、
Worker 继续经济。

## 18. Core 环形巡逻

安全状态：两个 Ranger 固定路线巡逻（非随机）；Core 附近危险立即回防；
不被敌人拉走；两侧扩大视野；危险结束恢复巡逻。

## 19. 手动覆盖

用户指令最高优先级但非永久任务（采矿完成自动恢复 AI）。

## 20. 状态持久化

保存地图记忆、资源记忆、敌人记忆、当前目标、路线、巡逻点——支持重启恢复、
长时间运行。

## 21. 服务稳定性

- 正常规划时间快速完成；极端情况（搜索爆炸）执行清理部分动作、提交安全
  方案、下一 Tick 重算；
- 网络异常：不重复提交、自动恢复连接。

## 22. 明确没有采用的方法

| 方法 | 原因 |
| --- | --- |
| LLM 每 Tick 控制 | 慢、不稳定、不确定 |
| 随机探索 | 浪费资源 |
| 只看最近目标 | 局部最优 |
| 人工固定路线 | 无法适应变化 |

## 23. 算法本质总结

> 一个以 Core 生存为约束，通过全局任务分配、A* 路径规划、地图记忆、资源
> 经济循环、敌人预测和确定性状态机实现长期自主运行的 RTS Agent。

```
                Game State
                    |
              State Manager
                    |
        -------------------------
        |           |            |
   Resource     Threat       Map Memory
   Planner      Planner      Explorer
        |           |            |
        -------------------------
                    |
              Global Planner
                    |
             Action Scheduler
                    |
                Tick Submit
```
